## 📌 문제 요약

`FOOD_PRODUCT` 테이블에서 **가장 비싼 상품의 정보**를 조회한다.

---

## 🧠 핵심 아이디어

* **서브쿼리(Subquery)** 를 사용해 전체 상품 중 **최대 가격(MAX(PRICE))** 을 먼저 구한다.
* 외부 쿼리에서 해당 가격과 **같은 상품만 필터링**한다.
* 최대 가격을 가진 상품이 **여러 개일 경우 모두 조회**된다.

---

## 💡 SQL 풀이

```sql
SELECT 
    PRODUCT_ID,
    PRODUCT_NAME,
    PRODUCT_CD,
    CATEGORY,
    PRICE
FROM FOOD_PRODUCT a
WHERE a.PRICE = (
    SELECT MAX(PRICE)
    FROM FOOD_PRODUCT
);
```

---

## 🔍 동작 과정 설명

1. **서브쿼리 실행**

   ```sql
   SELECT MAX(PRICE) FROM FOOD_PRODUCT
   ```

   → 전체 상품 중 가장 비싼 가격을 반환

2. **외부 쿼리에서 필터링**

   ```sql
   WHERE a.PRICE = (최대 가격)
   ```

   → 최대 가격과 같은 상품만 선택

---

## ✅ 결과 특징

* ✔ 가장 비싼 상품 **1개 또는 여러 개** 조회 가능
* ✔ 정렬(`ORDER BY`) 불필요
* ✔ NULL 이슈 없음 (MAX는 NULL 무시)

---

## 🧩 다른 풀이 방법 (비교용)

### 1️⃣ ORDER BY + LIMIT (MySQL 기준)

```sql
SELECT 
    PRODUCT_ID,
    PRODUCT_NAME,
    PRODUCT_CD,
    CATEGORY,
    PRICE
FROM FOOD_PRODUCT
ORDER BY PRICE DESC
LIMIT 1;
```

**⚠️ 주의**

* 최대 가격 상품이 여러 개여도 **1개만 반환**
* MySQL 전용 (`LIMIT`)

---

### 2️⃣ 윈도우 함수 사용 (고급)

```sql
SELECT 
    PRODUCT_ID,
    PRODUCT_NAME,
    PRODUCT_CD,
    CATEGORY,
    PRICE
FROM (
    SELECT *,
           MAX(PRICE) OVER() AS MAX_PRICE
    FROM FOOD_PRODUCT
) t
WHERE PRICE = MAX_PRICE;
```

**📌 장점**

* 서브쿼리 없이 전체 흐름을 한 번에 표현
* 대용량 분석 쿼리에서 자주 사용

---

## ⏱ 시간 복잡도

* `MAX(PRICE)` : **O(N)**
* 전체 쿼리 : **O(N)**

> 인덱스(`PRICE`)가 있다면 성능은 더 좋아질 수 있음

---

## 📝 정리 포인트 (면접/코테용)

* **최댓값 조건 필터링 → 서브쿼리**
* **여러 행 반환 가능 여부** 꼭 체크
* `ORDER BY + LIMIT` vs `MAX()` 차이 구분
