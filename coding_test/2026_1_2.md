# 📺 백준 1107번 – 리모컨

## 🧩 문제 요약

TV 리모컨에는 다음 버튼이 있다.

* 숫자 버튼: `0 ~ 9`
* 이동 버튼: `+`, `-`
* 시작 채널: `100`

일부 숫자 버튼이 고장 났을 때,
**채널 `N`으로 이동하기 위한 최소 버튼 클릭 횟수**를 구하라.

---

## 🔍 핵심 아이디어

이 문제의 핵심은 **이동 방식이 딱 두 가지뿐**이라는 점이다.

### 가능한 경우는 딱 두 가지

1️⃣ **숫자 버튼을 전혀 사용하지 않는 경우**

* `100 → N`
* 필요한 클릭 수:

  ```
  abs(N - 100)
  ```

2️⃣ **어떤 채널 `c`를 숫자로 입력한 뒤 `+ / -`로 이동**

* 숫자 버튼으로 `c` 입력
* 이후 `|N - c|` 만큼 `+ / -`
* 총 클릭 수:

  ```
  len(str(c)) + abs(N - c)
  ```

👉 이 두 경우 중 **최솟값이 정답**

---

## 🚫 BFS가 비효율적인 이유

처음 보면 그래프 최단 거리 문제처럼 보여서 BFS를 떠올리기 쉽다.

하지만 ❌ **BFS는 이 문제에 적합하지 않다.**

### BFS가 비효율적인 이유

* 채널 범위가 최대 **1,000,000**
* 거의 모든 채널이 방문 대상이 됨
* `distance 배열 + 큐` → 메모리 낭비
* 문자열 변환 + 검사 비용 큼

👉 **완전탐색이 더 단순하고 빠름**

---

## ✅ 정석 풀이 전략 (완전 탐색)

### 풀이 흐름

1. 기본값 설정

   ```python
   ans = abs(N - 100)
   ```

2. `0 ~ 1,000,000` 까지 모든 채널 `c`에 대해

   * 숫자 버튼으로 입력 가능한지 검사
   * 가능하다면:

     ```python
     ans = min(ans, len(str(c)) + abs(N - c))
     ```

3. 최종 `ans` 출력

---

## 💡 왜 1,000,000까지 확인할까?

* `N ≤ 500,000`
* 모든 숫자 버튼이 고장난 극단적인 경우
* 가장 가까운 입력 가능한 채널이 **6자리 이상**이 될 수 있음

👉 안전하게 `1,000,000` 까지 보면 충분

---

## 🧪 예외 케이스 체크

| 상황       | 처리 방식              |
| -------- | ------------------ |
| 고장 버튼 0개 | 숫자 입력이 항상 가능       |
| 모든 숫자 고장 | `abs(N - 100)`이 정답 |
| N = 100  | 정답은 0              |
| N = 0    | `"0"` 입력 가능 여부 확인  |

---

## 🧠 구현 코드

```python
N = int(input())
M = int(input())

broken = set()
if M > 0:
    broken = set(input().split())

def can_type(x: int) -> bool:
    for ch in str(x):
        if ch in broken:
            return False
    return True

ans = abs(N - 100)

for c in range(0, 1_000_001):
    if can_type(c):
        ans = min(ans, len(str(c)) + abs(N - c))

print(ans)
```

---

## ⏱️ 시간 & 공간 복잡도

### 시간 복잡도

* `O(1,000,000 × 자릿수)`
* 자릿수 최대 7 → **충분히 통과**

### 공간 복잡도

* `O(1)`
* 추가 배열 없음
