---

## 📌 문제 개요

`PLACES` 테이블에서
**같은 HOST_ID가 2개 이상의 장소를 등록한 경우**,
해당 HOST가 등록한 **모든 장소 정보**를 조회하는 문제이다.

---

## 🎯 요구 사항 정리

* HOST_ID 기준으로 **2개 이상 등록한 호스트만 대상**
* 해당 HOST가 등록한 **모든 장소(ID, NAME, HOST_ID)** 출력
* 결과는 **ID 기준 오름차순 정렬**

---

## 🧠 핵심 아이디어

이 문제는 **2단계 접근**이 핵심이다.

### 1️⃣ 조건을 만족하는 HOST_ID 먼저 찾기

* `GROUP BY HOST_ID`
* `HAVING COUNT(*) >= 2`

### 2️⃣ 원본 테이블과 JOIN

* 조건을 만족한 HOST_ID만 다시 붙여서
* **전체 장소 행**을 가져온다

---

## 🧾 SQL 코드

```sql
WITH b AS (
    SELECT HOST_ID
    FROM PLACES
    GROUP BY HOST_ID
    HAVING COUNT(*) >= 2
)

SELECT a.ID, a.NAME, a.HOST_ID
FROM PLACES a
JOIN b ON a.HOST_ID = b.HOST_ID
ORDER BY a.ID;
```

---

## 🔍 쿼리 단계별 설명

### 📍 1. CTE (WITH 절)

```sql
WITH b AS (
    SELECT HOST_ID
    FROM PLACES
    GROUP BY HOST_ID
    HAVING COUNT(*) >= 2
)
```

* `HOST_ID` 기준 그룹화
* 장소를 **2개 이상 등록한 HOST_ID만 추출**
* 결과 예시:

```text
HOST_ID
-------
101
205
```

---

### 📍 2. 메인 쿼리

```sql
SELECT a.ID, a.NAME, a.HOST_ID
FROM PLACES a
JOIN b ON a.HOST_ID = b.HOST_ID
```

* CTE에서 걸러진 HOST_ID만 대상으로
* 해당 HOST가 등록한 **모든 장소 행**을 조회

---

### 📍 3. 정렬

```sql
ORDER BY a.ID
```

* 문제 요구사항에 맞게 ID 기준 오름차순 정렬

---

## ❓ 왜 WHERE가 아니라 JOIN인가?

❌ 잘못된 접근:

```sql
WHERE COUNT(*) >= 2
```

→ **집계 결과는 WHERE에서 사용 불가**

✅ 올바른 방법:

* `HAVING`으로 그룹 조건 처리
* 결과를 다시 JOIN

---

## 🔄 대체 풀이 (서브쿼리)

CTE 없이도 이렇게 작성 가능하다:

```sql
SELECT ID, NAME, HOST_ID
FROM PLACES
WHERE HOST_ID IN (
    SELECT HOST_ID
    FROM PLACES
    GROUP BY HOST_ID
    HAVING COUNT(*) >= 2
)
ORDER BY ID;
```

### ✔ 비교

| 방식         | 장점            | 단점          |
| ---------- | ------------- | ----------- |
| CTE + JOIN | 가독성 좋음, 확장 쉬움 | 줄 수 많음      |
| IN 서브쿼리    | 짧고 간결         | 복잡해지면 가독성 ↓ |

---

## ⚙️ 실행 관점 (성능)

* `HOST_ID`에 인덱스가 있으면
  → `GROUP BY` + `JOIN` 모두 효율적
* 대용량 테이블에서도 안정적인 패턴

---
