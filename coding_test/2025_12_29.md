# 🏰 공주님을 구해라! (BFS + 상태 관리)

## 📌 문제 요약

* `N x M` 성
* 시작 `(0,0)` → 도착 `(N-1,M-1)`
* 제한 시간 `T`
* 맵 정보

  * `0` : 빈 칸
  * `1` : 벽 (통과 불가)
  * `2` : 그람(검)

### ⚔️ 그람 효과

* 그람 획득 후 → **모든 벽 무시 가능**
* 이동 시간은 항상 1

---

## 💡 풀이 핵심 아이디어

👉 **"그람을 가지고 있는가?" 자체가 상태다**

그래서 일반 BFS가 아니라:

```
(x, y, 시간, have_gram)
```

### 방문 배열도 3차원

```python
visited[gram_state][x][y]
```

* `gram_state = 0` → 검 없음
* `gram_state = 1` → 검 있음

---

## 🧠 알고리즘 설명 (Step-by-Step)

### 1️⃣ 초기 설정

```python
queue.append((0, 0, 0, False))
visited[0][0][0] = True
```

---

### 2️⃣ BFS 진행

#### ⏱️ 시간 초과 체크

```python
if T < t:
    continue
```

---

#### 🎯 목적지 도착 시

```python
if (x, y) == (N - 1, M - 1):
    answer = min(answer, t)
    continue
```

> BFS라서 **최초 도착이 항상 최소는 아님**
> → 그람 루트 vs 일반 루트 둘 다 고려해야 함

---

### 3️⃣ 이동 규칙

#### ⚔️ 그람이 있을 때

```python
# 벽 무시
visited[1][nx][ny]
```

* 모든 칸 이동 가능

---

#### 🚶 그람이 없을 때

```python
board[nx][ny] != 1
```

* 벽은 못 감
* `2`를 만나면 → **그람 상태 전이**

```python
visited[0][nx][ny] = True
visited[1][nx][ny] = True
```

👉 이게 진짜 중요한 포인트
**그람 획득 순간부터는 두 상태 모두 방문 처리**

---

## ⏱️ 시간 & 공간 복잡도

### 시간 복잡도

```
O(N × M × 2)
```

* 각 칸을

  * 그람 없음
  * 그람 있음
* 두 번까지만 방문

### 공간 복잡도

```
O(N × M × 2)
```

## 🔥 최적화 & 다른 관점 풀이

### 1️⃣ 조기 종료 가능?

👉 **불가능**

이유:

* 그람 없이 가는 루트
* 그람 들고 돌아가는 루트
  → 어느 쪽이 더 빠를지 중간엔 모름

---

### 2️⃣ 다익스트라로 풀 수 있을까?

❌ 비효율적

* 가중치가 전부 1
* 상태만 추가하면 BFS가 최선

---

### 3️⃣ 수학적 shortcut (이 문제에서만 가능)

그람 위치를 `(gx, gy)`라고 하면:

```
start → gram (BFS)
gram → end (맨해튼 거리)
```

이걸 비교하는 방식도 있음
⚠️ 단점: **벽 구조에 따라 예외 많음**

👉 **실전에서는 지금 BFS가 제일 안전**
